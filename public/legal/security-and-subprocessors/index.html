Security and Sub-processors

Last updated 14 October 2026

1. Our approach

Law firms hold some of the most sensitive information there is. FirmTrack is built so that each firm's data is separated from every other firm's, and so that access is limited to what each person needs.

2. Technical and organizational measures

  • Tenant isolation: every record belongs to an organization and is protected by database row-level security, so one firm's users cannot read another firm's data.
  • Server-side secrets: privileged keys and credentials are held only on the server and never sent to the browser.
  • Encryption: data is encrypted in transit with TLS, and at rest by our database provider. To confirm: confirm encryption-at-rest and backup details with Supabase plan in use
  • Sign-in: authentication goes through Microsoft Entra ID, so your firm's own multi-factor authentication and conditional access policies apply.
  • Least privilege: role-based access within each workspace, and restricted staff access to production systems. To confirm: confirm internal access controls and logging
  • Audit logging: key actions in workspaces are logged.
  • Backups and recovery: To confirm: backup frequency, retention and restore testing
  • Secure development: code review, dependency updates and separate environments for development and production. To confirm: CONFIRM

3. Incident response

We maintain an incident response process. If a breach affects customer data we notify affected customers without undue delay and within 72 hours of becoming aware, as set out in the Data Processing Addendum.

4. Reporting a vulnerability

Email security@firmtracks.com. See the Security testing section of the Acceptable Use Policy.
